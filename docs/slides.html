What is the Portal?

A curated discovery layer across distributed resources

  • A complement to existing platforms (GitHub, BioPortal, BSSO Foundry, Zenodo)
  • An evolving index of Network outputs
  • A transparent entry point for all audiences
  • Infrastructure that can grow without centralizing everything

Aim 1: FAIR-compliant public-facing portal  |  Aim 3: Resource "toolbox"

Core Principle

Link, don’t duplicate.
Curate, don’t automate.
Complement, don’t compete.

The portal is metadata + links.
Content stays where it lives.

Who is This For?

Beginners

“I don’t know what I don’t know.”

Guided discovery — browse by project, topic, type

Advanced Users

“I know what I need.”

Efficient access — search, filter, direct links

Funders

“What has the Network produced?”

Visibility — stats, overview, breadth of outputs

What a Resource Looks Like

id: bcio
name: Behaviour Change Intervention Ontology (BCIO)
type: Ontology
description: >
  An ontology for annotating and synthesising evidence
  about behaviour change interventions.
project: Cross-cutting
links:
  - label: BioPortal
    url: https://bioportal.bioontology.org/ontologies/BCIO
    platform: BioPortal
  - label: GitHub
    url: https://github.com/HumanBehaviourChangeProject/ontologies
    platform: GitHub
bssoFoundry: true
tags: [ontology, behaviour-change, interventions]
status: Active

One YAML file per resource — version-controlled in Git, easy to update via PR

Inclusion Criteria

A resource is included if:

  1. It is a product of, or directly relevant to, a Network project
  2. It has at least one accessible public link
  3. It is vouched for by a Network member
  • Initially curated by DCC; later open to submissions via PR or form
  • “In Development” resources welcome — inclusion is not endorsement of completeness
  • Lightweight by design — low barrier to add a resource

Open Questions

  1. Hosting — Where should the portal live? (institutional vs. cloud)
  2. Governance — Who can add/update resources long-term?
  3. Automation — Should we pull metadata from APIs (GitHub, BioPortal)?
  4. Scope — What other resource types should we include?
  5. Metrics — What analytics do funders need?
  6. Integration — Relationship with the BSSO BioPortal slice?

Roadmap
